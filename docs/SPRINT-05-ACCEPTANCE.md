# Sprint 05 人工验收

本页在 Sprint 01–04 验收基础上追加。请使用日常库中自己创建的材料；自动化测试的示例与截图来自隔离数据库，不会自动导入日常库。

## 准备数据

1. 以 admin 登录，新增一种材料，单位“个”、单价 `0.1234`、安全库存 `100`。
2. 入库 `100` 个，记下批次号。库存恰好为安全库存，本轮预警应已恢复。
3. 以 student 登录，从这个批次领用 `20` 个，填写项目号、用途及选填课程。余额应为 `80`，额度累计为 `20`。

## 完好归还

1. 以 admin 或 lab 登录「归还与报废」，点击「登记归还」。按原单号、领用人或材料搜索并选中领用单。
2. 明细应显示原领用 `20`、已归还 `0`、可归还 `20` 和原批次号。
3. 填本次归还 `5`，确认。打开归还详情，检查关联领用单、操作人、RETURN 流水和库存 `80 → 85`；刷新后仍可查询。
4. 再归还 `8`，可归还量变为 `7`。输入 `8` 应被前端范围及后端累计校验拒绝；归还 `7` 后余额为 `100`，预警自动恢复。
5. student 只能查看自己的归还，不能登记归还。归还后原月度已领量仍为 `20`。
6. 如网络中断导致结果未知，页面出现待确认操作；刷新后使用「安全重试原请求」，不可重复增加库存。收到明确校验错误后可修改重新登记。

## 仓库报废与照片

1. admin / lab 选择「报废记录」→「登记报废」，搜索材料并选中库存批次。
2. 输入 `3`，填写原因，可上传 JPG / PNG / WebP。照片保存成功后显示文件名及认证预览。
3. 确认报废，余额应 `100 → 97`；详情保留原因、操作人、时间、SCRAP 流水和照片。刷新后不丢失。
4. 数量超过余额、非正数、缺少原因、假图片和超过 5 MB 的图片应失败。照片保存失败时应有明确提示，可重新上传或显式移除照片继续。
5. 记录不能经普通接口修改或删除。已领出损坏材料不能再次扣仓库。

## 预警与邮件

1. 「库存预警」搜索本材料，检查当前 `97` / 安全库存 `100`、状态和时间。
2. 打开详情，填写处理备注并确认；状态变为“已确认”，不会立即解除低库存。采购员也可确认，教师只能查看。
3. 本机没有配置 SMTP 时显示“未配置”，并写明原因；站内预警照常工作，不显示发送成功。
4. 再入库 `3`，当前达到 `100`，预警自动“已恢复”；再次报废 `1` 产生新一轮活动预警。反复扫描不会在持续低库存中重复创建。
5. 可修改安全库存或点击「重新扫描库存」验证升级前低库存也会补建事件。安全库存为 `0` 不触发。
6. 如自愿配置自己的 SMTP，按 README 配置环境变量并重启后，对未配置 / 失败通知点「重试邮件通知」。检查真实邮箱及状态。自动化只使用受控本地 SMTP，未验证任何外部邮箱投递。

## 报表中心

1. admin 打开「数据报表」，核对默认学期的具体起止日期；自定义日期包含上述操作当天。
2. 按材料编码查询：「学期耗材」领用 `20`、归还 `20`、净消耗 `0`；报废独立统计，不能算成用户再次领用。不同币种、单位分别汇总。
3. 在「经费对应」按项目号 / 课程筛选，检查原领用单价 `0.1234` 和项目归属。修改档案现价后，历史金额应不变。
4. 「个人领用」选择 student，预览真实明细、用途、原批次、累计归还和本期净消耗。
5. 三个页签各点一次 Excel 和 PDF，总共六份文件。检查中文、标题、日期范围、数量、金额及汇总。Excel 表头冻结；PDF 必要时分页并重复表头。
6. 筛选无记录时仍可导出合法空报表。学生登录只见个人页签，不能通过 userId 查询或导出他人记录。
7. 跨期归还按实际归还日期冲减；仅有归还的期间净消耗允许为负。

## 回归与移动端

- 原材料档案、入库、二维码、领用、限额、原 PDF 凭证及退出登录仍正常。
- 手机宽度下操作使用卡片 / 抽屉，报表筛选换行，页面本身不横向溢出。
- 用户与权限 / 系统设置仍是后续开发页面。本轮没有 Push 或云部署。

开发者已执行的自动化结果见 [Sprint 05 记录](SPRINT-05.md)。人工验收状态由用户填写，开发者不代为宣称通过。
