### 架构与技术决策

| 决策 | 原因 |
| --- | --- |
| React 19 / TypeScript 5.9 / Vite 7 | 简单 SPA，开发代理与静态部署清晰；锁定 package-lock 保证可复现 |
| Ant Design 5 定制 Token 与独立 CSS | 使用成熟表单和交互组件，保留品牌、布局与视觉一致性 |
| Java 17 / Spring Boot 3.5.16 | 保持 Spring Boot 3 技术栈，选用已发布的 3.5 系列稳定补丁 |
| MyBatis-Plus 3.5.12 | 用户查询与后续业务 CRUD 的简洁基础 |
| Spring Security OAuth2 JOSE / Nimbus JWT | 使用现成签名、解码和标准 Bearer 认证链，避免自行实现密码学 |
| PostgreSQL 15 / Flyway | 正式数据库与测试数据库一致，迁移可追溯 |
| sessionStorage | 会话内恢复；不自动长期保存登录，刷新后仍向服务器校验 |
| 实时查询角色 | 角色和启用状态变更能影响已签发 JWT 的下一次请求 |

前后端分离部署，后端为单体应用，没有 Redis、微服务或消息队列。Controller / Service / Mapper / Entity / DTO 分层；固定 API 包装与集中异常处理。

### 实际完成功能

5. dev profile + 显式启用标记初始化三个演示账户；密码、数据库凭据与随机 JWT 密钥只写入被忽略的 .env。
6. 中文登录页、加载、校验、错误反馈、认证状态恢复、自动过期、退出与网络重试。
7. Apple 风格侧栏、工具栏、用户菜单、折叠导航、移动抽屉、键盘焦点和减少动画支持。

10. 403 / 404、Vite 代理、环境地址、可配置 CORS、Vercel SPA 重写与启动 / 测试文档。

### 关键实现

- 数据库不保存明文密码，BCrypt cost=12；演示账户仅在缺失时创建，不覆盖已有账户。
- JWT 密钥必须是至少 32 随机字节的 Base64；无生产默认值。默认有效期 2 小时。
- 令牌不包含可被客户端当作权威的角色；认证转换器每次读取数据库，角色检查使用 ROLE_ authority。
- 前端使用统一请求客户端处理超时、401 与错误格式。失败的旧请求不会清除后来建立的新会话。
- 临时网络故障保留现有令牌，显示身份恢复重试页；失效令牌被清除。
- 测试数据只写入 *_test 数据库，连接 URL 在 Spring 应用迁移前校验。未使用 H2 或假登录替代验收。
- 概览接口明确返回 businessAvailable=false；业务数据全部为空，没有将模拟记录包装为真实功能。
- 开发文档从工程初始化时建立，随实现与验证持续更新。
