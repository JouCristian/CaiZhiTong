# v0.7.0 · GitHub 登录与只读公开体验

开发日期：2026-11-04（Asia/Shanghai）。基于 v0.6.0 增量开发，分支 `feat/github-oauth-login`。本记录随实现更新，尚未执行的验证不会记为通过。

## 目标与边界

保留用户名密码、JWT 和六类角色。使用 Spring Security OAuth2 Client 连接 GitHub，不引入 Supabase Auth。新 GitHub 账户默认 GUEST，仅查询独立 Demo 材料、库存与批次；不开放匿名写入，不自动授予学生、实验员或管理员。管理员可通过既有用户页面调整角色、停用或明确重置密码。

## 认证与持久化

- Spring 标准授权码流程、随机 state、服务端 10 分钟临时 Session，provider 端同时使用 PKCE。只申请 `read:user`，不请求邮箱 scope，不导入 provider 邮箱。
- 只有 OAuth 握手使用 Session；原业务 API 仍为 stateless JWT。成功 / 失败均失效握手 Session，不保存 GitHub access / refresh token。
- V7 增加 oauth_identity，以 `(provider, provider_user_id)` 唯一关联本地用户。采用数据库事务锁和唯一约束防并发注册。用户名使用系统随机命名空间，不按 GitHub 用户名或邮箱接管已有账户。
- 新 OAuth 账户 password_login_enabled=false，使用随机 BCrypt 哈希；原用户默认 true。管理员明确重置密码才可开启密码入口，不影响继续使用 GitHub。
- 回调生成 60 秒交换码，仅哈希入库，并绑定前端 S256 verifier 和当前 auth_version。前端 URL fragment 只携带短时码，立即清除，再 POST 交换现有 JWT；一次使用后删除，过期 / 错误 verifier / 被撤销会话拒绝交换。
- 再次 GitHub 登录只更新身份表中的 handle / 安全头像，不覆盖本地权限、密码、姓名或邮箱。停用账户拒绝 OAuth 登录，既有 JWT 仍按原机制实时撤销。
- 仅接受 avatars.githubusercontent.com 的 HTTPS 用户头像，无 referrer；加载失败显示本地姓名首字。

## 只读权限与隐私

GUEST-only 仅使用独立 demo_* 表、专用 GET API 与演示导航。全部正式 `/api/**`（除明确公开认证 / 系统元数据和本人 me）必须先具有五种业务角色之一；游客不能读取正式材料、库存、工作台、兼容批次、二维码、流水、私人附件、报表或任何业务写入。删除早期游客批次字段脱敏代码，避免将脱敏误认为隔离。混合角色与原业务 Controller 权限保持兼容。

V7 在尚未发布的迁移中增加四张 Demo 表，V1–V6 原文件保持不变。初始化只写 demo_*，不删除或覆盖管理员与正式材料 / 库存。完整边界、数据与测试方法见 [演示隔离设计](DEMO-ISOLATION.md)。

## GitHub OAuth App：已完成配置与生产边界

账户持有人已创建生产 GitHub OAuth App，并执行私密配置脚本。本机已安全保存 Client ID、Client Secret、回调地址与仅供回归的现有云管理员密码；检查仅输出“已配置”布尔值，不输出内容。本轮无需重建 App 或重新索取凭据。生产 Render 尚未启用 OAuth。

| 字段 | 生产值 |
| --- | --- |
| Application name | CaiZhiTong |
| Homepage URL | https://caizhitong-eight.vercel.app |
| Authorization callback URL | https://caizhitong-api.onrender.com/login/oauth2/code/github |

用户最终确认合并与启用后，才将已保存的 OAuth 凭据写入 Render 后端环境。回归管理员密码不上传 Render，不恢复 bootstrap 密码或初始化开关。下表为占位示例：

```dotenv
GITHUB_OAUTH_ENABLED=true
GITHUB_CLIENT_ID=REPLACE_WITH_OAUTH_APP_CLIENT_ID
GITHUB_CLIENT_SECRET=REPLACE_WITH_PRIVATE_OAUTH_APP_SECRET
GITHUB_REDIRECT_URI=https://caizhitong-api.onrender.com/login/oauth2/code/github
PUBLIC_WEB_URL=https://caizhitong-eight.vercel.app
CORS_ALLOWED_ORIGINS=https://caizhitong-eight.vercel.app
```

其他开发者部署时应在自己的 GitHub Settings → Developer settings → OAuth Apps 创建独立 App，Homepage 为自己的前端源，Callback 为自己的后端 `/login/oauth2/code/github`；不要复用本项目生产凭据。

Vercel 不需要 GitHub secret；继续使用原 API 地址和 240 秒冷启动等待。cloud profile 设置 Secure / HttpOnly / SameSite=Lax 会话 Cookie，使用显式 callback URL，不根据 Host / X-Forwarded-* 拼接。多域名或开发回调需要独立 OAuth App，不能把预览域名随意加入生产配置。

默认 GITHUB_OAUTH_ENABLED=false，没有凭据时密码登录仍正常。配置接口先唤醒 Free 后端，再允许发起 OAuth；握手中实例重启或超时需重新登录，不降低 state 校验。
